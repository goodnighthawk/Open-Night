# Integration

1. Load `config/paired_parts.csv` and expose only rows with `selectable=true`.
2. Present choices grouped by `slot`; the same part ID is used in both cameras.
3. Validate head/top and accessory/head selections with `config/compatibility_rules.csv`.
4. Crop the selected mode's sheets with 256 px cells. Direction columns follow `config/directions.csv`: north, northeast, east, southeast, south, southwest, west, northwest. Fluid sheets use the same order as direction rows.
5. Composite body, top, bottom, footwear, head, accessory.
6. `runtime/character_customizer.py` implements the Pygame path and `runtime/character_customizer.js` implements the browser Canvas path.
7. The motorcycle helmet is a complete `head` choice, not an accessory overlay.
8. Do not stretch top-down cells vertically. Their reference-guy foreshortening and single-lead-leg walking silhouette are part of the approved camera contract.
9. Use the feet/ground-contact anchor for world occlusion. In strict top-down mode, stable-sort renderables by `(ground_y, world_x, entity_id)` and draw from smallest to largest. This allows buildings, vehicles, trees, props and other actors to pass correctly behind or in front of the character.
10. Cardinal directions remain the original approved pixels. Strict top-down diagonals are exact 45° ground-plane rotations; isometric diagonals use a registered soft split between adjacent upright views. Both are generated by `tools/add_diagonal_directions.py`; use the tool only when migrating a four-facing compatible source pack.
11. Apply continuous middle-mouse camera rotation and mouse-wheel zoom around the local-player pivot. Use the configured 1.0 default, 0.55–2.0 range and 0.10 step; scale the whole world but not fixed UI. Convert screen-relative WASD with `screen_to_world_delta`, transform cursor aim independently, lock the local sprite to north/screen-forward during active drag, and leave the minimap north-up.
12. Re-sort ground-contact anchors after every camera-angle change using `rotated_depth_sort_key`; unrotated world Y is no longer sufficient once the camera has turned.
13. A single jump carries the actor forward at the configured doubled range. A valid second Space press changes to the doubled-range double-jump impulse, renders slightly larger than the first jump, and forces a prone landing. Hold either Shift key with directional input for the 3.0× run; perpendicular held input may form a running diagonal. While running, select `run_wide_8` rather than speeding up `walk_8`: the dedicated sheets widen the peak gait to 1.48× while preserving the ground anchor and strict top-down camera. Custom combinations without a profile sheet must use the lower-body widening fallback. Releasing Shift, stopping, crouching, going prone, jumping or starting an action stops running. Directional input while crouched or prone begins the configured one-second stand transition and moves only after it completes; either Space or X stands immediately, and X toggles prone. The multiplayer server owns the final action state and broadcasts `jump`, `double_jump`, `crouch`, `prone`, and `run` poses to every nearby client.
14. Reset the automatic idle timer on movement, actions, crouch or prone. Use `config/idle_settings.csv` to select `breathing_6` after the settle delay and `waiting_12` during deterministic waiting windows. Authored fluid profiles use the registered sheets in `config/fluid_animations.csv`; custom modular combinations may use the same upper-body breathing transform and row-4 waiting fallback demonstrated by the tester. Never move the ground-contact anchor or expose extra legs in strict top-down idle frames.
